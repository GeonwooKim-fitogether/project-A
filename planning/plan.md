## ① 대상 로드맵 단계
- R-2 구조·문서 지도 (docs 링크 마무리)
- R-3 정합 유지

| 번호 | 작업 | 연결 목표 | 등급 | 순서 |
|---|---|---|---|---|
| P-1 | README 의 존재하지 않는 `docs/github-project-sync.md` 링크 한 줄 정리 | G-2 | tier:low | 1 |
| P-2 | README 시스템층 설계 문서 절에 미연결 docs 문서 7개 링크 추가 | G-2 | tier:low | 2 |

## ③ 위험·의존 관계
- 5건 모두 `README.md` 를 고치므로 동시에 착수하면 병합 충돌 가능성 있음. 위에서부터 한 건씩 병합 후 다음 건 착수 권장
- P-1 은 파일이 이 저장소에 없는 사실만 근거로 함. 링크 줄을 지우는 방향으로 처리하며, 문서를 새로 만들지 않음
- P-3·P-4 는 워크플로 동작을 설명하는 문장을 다루므로 `autonomy-tiers.md` 1절의 낱말 기준(배포·권한 등)에 걸릴 수 있어 애매한 경우로 보고 한 등급 올려 tier:mid 로 판정함. 워크플로 파일 자체는 바꾸지 않음
- P-5 는 권한·훅 설명을 다루고 "permission" 낱말이 diff 에 들어가므로 상 목록의 낱말 기준에 닿는 것으로 보고 tier:critical 로 판정함. 설정 파일(`.claude/settings.json`)과 훅은 바꾸지 않고 README 문장만 고침. `tier:critical` 이라 `auto` 라벨 없이 이슈만 등록되며 착수는 건우님이 결정함
- 열린 이슈와 최근 병합 PR 은 없으므로 겹치는 항목 없음. 4회차 이전 백로그(README 기획 폴더·자율 루프·저장소 구조 절 추가)는 README 에 이미 반영된 것을 확인해 다시 넣지 않음
- 자율 루프 실행 스크립트와 동기화 봇 실행은 이 저장소에서 하지 않음. README 설명은 워크플로 파일의 머리말과 `on:` 조건만 근거로 씀

## ④ 의사결정 요청
- P-5 착수 여부 판단 요청(tier:critical). 승인하면 README 문장 정정만 진행하며 설정·훅 변경은 포함하지 않음
- P-3·P-4 를 tier:mid 로 둔 판정 확인 요청. tier:low 로 내려도 되면 기획 PR 의견으로 알려 주시면 됨
- 참고 — 함께 발견한 것(지시 없으면 착수하지 않음):
  - README "변경 이력" 절이 구 저장소 PR 번호 기준 6줄뿐이며 이 저장소 PR 과 이어지지 않음. 이력 줄을 PR 마다 별도 PR 로 더하는 방식은 PR 수와 Actions 사용량을 늘리므로 운영 방식 재검토 필요
  - `docs/milestones.md`·`docs/plan-review.md` 등이 가리키는 로컬 설계 원문(`_grr/designs/`)은 이 저장소에 없음
