## ② 문서별 작성 기준

- **목적**: 배경 · 목적 · 성공 판단 기준(건우님이 "됐다"고 볼 관찰 가능한 기준) · 범위 밖 · 입력(시드·갱신일). 회차가 바뀌어도 유지, 방향 재설정 때만 변경
- **목표**: 최대 3건, 목표마다 측정 기준·기한·상태(완료 / 진행 중 / 미착수)
- **로드맵**: 흐름도 축. 단계별 완료 기준 명시, mermaid 도표와 표를 함께 두고 변경 이력을 남김. 개발 중 발견한 문제를 반영함
- **계획**: 대상 로드맵 단계 · 작업 묶음(연결 목표·등급·순서) · 위험·의존 관계 · 의사결정 요청
- **백로그**: 아래 3절 형식 엄수. 이슈 등록의 원천이므로 형식 오류 시 등록되지 않음

## ③ 백로그 항목 형식

```
## B-001 docs: <무엇을 하는지 한 문장>
- 등급: tier:low
- 목표: <완료 시 달라지는 점>
- 배경: <필요한 이유>
- 완료 조건:
  - [ ] <확인 가능한 조건>
- 범위 밖: <하지 않을 것>
- 근거: 계획 P-1 / 목표 G-1
```

- 제목 `## B-<세 자리 번호> <종류>: <한 문장>`, 종류는 feat · fix · docs · chore · refactor · mig
- 항목 하나 = PR 하나 크기, 단독 반영 가능해야 함
- 회차당 최대 5건, 위에서부터 착수 순서
- 등급 판정은 [품질 기준서](./quality.md)와 `.claude/rules/autonomy-tiers.md` 를 따름

## ④ 검토·승인

| 판단 | 방법 | 이후 처리 |
|---|---|---|
| 승인 | 기획 PR 에 `plan-approved` 라벨 또는 반영 | 백로그를 과제로 등록 |
| 수정 | 의견 작성 후 `plan-revise` 라벨 | CC-기획이 같은 PR 갱신 |
| 보류 | `plan-hold` 라벨 | 등록·보충 중지 |

- `tier:critical` 항목은 `auto` 라벨 없이 과제만 등록, 착수는 건우님 결정
- 열린 `auto` 과제가 3건 미만이고 검토 중인 기획 PR 이 없으면 CC-기획이 다음 회차를 자동 기획함

## ⑤ 기획 원칙

- 큰 틀은 건우님과 합의, 나머지는 자율 (이 시스템의 모토)
- 계획 없이 착수 금지: 목적 → 목표 → 로드맵 → 계획 → 백로그 순서를 지킴 (11-27 위반 사례 있음)
- 로드맵은 전체를 어떻게 끝낼지 보여주는 시각 도표여야 하며, 한 단계만 다루지 않음
- 일정은 AI 작업 속도 기준으로 분·시간·일 단위로 추정함, 주·월 단위 장기 일정 금지 (11-27 건우님 지적)
- 흐름도 틀을 바꾸는 기획 변경은 [보고 기준서](./report.md) 1원칙에 따라 사전 확인함

## ⑥ 점검표 (기획 PR 제출 전)

- [ ] 목적·목표·로드맵·계획·백로그가 순서대로 갖춰져 있음
- [ ] 목표 3건 이내, 측정 기준 명시
- [ ] 로드맵이 전체 완주까지 도표로 보임
- [ ] 백로그 항목이 형식을 지키고 5건 이내이며 단독 반영 가능함
- [ ] 항목마다 등급 라벨이 판정되어 있음
- [ ] 일정이 분·시간·일 단위 현실 추정임
- [ ] 의사결정 요청이 한 줄 이내로 정리됨
